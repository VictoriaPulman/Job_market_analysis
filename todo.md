## 💻 Перенос проекта на другой компьютер (Windows)
⚠️ **ВАЖНО:** Никогда не копируйте папку `.venv` на другой компьютер! Она привязана к путям текущей системы и работать не будет.
- [ ] При переносе скопировать файл TODO.md и requirements.txt (если он есть). Исходные блокноты и папка .venv не переносятся.
- [ ] На новом компьютере открыть папку в VS Code и заново выполнить весь чек-лист с первого шага.

## 🍏🐧 Справка: Эквиваленты команд для macOS и Linux
Если проект потребуется запустить на Mac или Linux, используйте эти команды вместо Windows-версий:
* **Создание окружения:** `python3 -m venv .venv`
* **Активация окружения:** `source .venv/bin/activate`
* **Обновление pip (необязательно):** `python3 -m pip install --upgrade pip`
* **Установка библиотек:**
  * *Если есть файл:* `pip install -r requirements.txt`
  * *По отдельности:* `pip install pandas numpy seaborn matplotlib scipy`


## 🐙 Перенос проекта на GitHub / GitLab
- [x] Инициализировать Git-репозиторий в папке проекта
  * *Команда:* `git init`
- [x] Создать файл `.gitignore` в корневой папке проекта
  * *Для PowerShell:* `New-Item .gitignore -ItemType File`
  * *Для CMD:* `type nul > .gitignore`
- [x] Добавить в файл `.gitignore` игнорирование виртуального окружения и кэша
  * *Открыть файл и вписать строки (или скопировать):*
    ```text
.venv/
venv/
__pycache__/
.ipynb_checkpoints/
    ```
- [x] Создать файл `README.md` в корневой папке проекта
  * *Для PowerShell:* `New-Item README.md -ItemType File`
  * *Для CMD:* `type nul > README.md`
  * *Открыть файл и написать краткое описание (например):*
    ```text
    # Практический кейс: Анализ данных с помощью NumPy
    Репозиторий содержит практические материалы урока по анализу данных.
    ```

- [ ] Проверить статус файлов перед коммитом (убедиться, что папка `.venv` не попала в список)
  * *Команда:* `git status`
- [ ] Сделать первый коммит (сохранение) проекта
  * *Выполнить команды по очереди:*
    1. `git add .`
    2. `git commit -m "Initial commit"`
- [ ] Создать новый пустой репозиторий на сайте GitHub
  * *Шаг 1:* Зайти на GitHub и в верхнем правом углу нажать на **«+»** -> **New repository**.
  * *Шаг 2:* В поле **Repository name** ввести короткое имя проекта (например, `numpy_practice`).
  * *Шаг 3:* Сделать репозиторий **Public** (открытый) или **Private** (приватный) по вашему выбору.
  * *⚠️ Важное правило:* **Ничего больше не отмечать!** Оставьте галочки *Add a README file*, *Add .gitignore* и *Choose a license* **пустыми** (так как эти файлы мы уже создали вручную на компьютере, иначе возникнет конфликт).
  * *Шаг 4:* Нажать зеленую кнопку **Create repository**.
  * *Шаг 5:* Скопировать появившуюся ссылку на ваш репозиторий (она заканчивается на `.git`).
- [ ] Создать главную ветку репозитория
  * *Команда:* `git branch -M main`
- [ ] Связать локальную папку с пустым репозиторием на GitHub
  * *Команда (замените ссылку на свою):* `git remote add origin https://github.com/VictoriaPulman/NumPy.git`
- [ ] Отправить проект на GitHub (команда push)
  * *Команда для первой отправки:* `git push -u origin main`
### 🔒 Ошибка блокировки Email (push declined due to email privacy restrictions)
Если при первой отправке `git push` возникает ошибка приватности email, настройте скрытый адрес (сделать один раз на компьютере):
- [ ] Настроить этот email в локальном Git на компьютере
  * *Команда:* `git config --global user.email "81351659+VictoriaPulman@users.noreply.github.com"`
- [ ] Перезаписать автора последнего коммита под новую скрытую почту
  * *Команда:* `git commit --amend --reset-author --no-edit`
- [ ] Повторить отправку проекта на сервер
  * *Команда:* `git push -u origin main`

### 🔄 Последующая отправка обновлений (Для ежедневной работы)
Когда вы изменили код и хотите отправить свежую версию на GitHub, выполните в терминале:
1. `git add .` *(выбрать все измененные файлы)*
2. `git commit -m "описание того, что вы изменили"` *(зафиксировать изменения локально)*
3. `git push` *(вытолкнуть обновление на GitHub)*
